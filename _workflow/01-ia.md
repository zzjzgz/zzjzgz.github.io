# 01 · 信息架构与黄金任务流（S1）

## 黄金任务流（1 条，走通）
```
外部入口（README / 分享 / 搜索）
  → P1 首页：一句话主张 + v0.5.6 真实界面截图，建立「这是个本地小工具」的第一印象
  → P2 为什么：三个「不」（不上传 / 不评判 / 不收费），解决信任问题
  → P3 界面：四个视图切换（今天 / 趋势 / 应用 / 事件），确认功能够用
  → 数据属于你 + 隐私边界：确认数据能搬走、能删掉、内容不被记录
  → 规格：版本、技术栈、体积、平台、许可，给技术型访客一个核对点
  → P5 下载：单个 setup 按钮（顶部导航 / 首屏可同链直达）
  → FAQ：扫清联网、上传、换机、平台、源码的剩余疑问
业务结果：访客到达发布仓并选择产物下载。
```

区段与业务流的对应：`P1 → P2 → P3 → P4 → P5`，中间两节（数据属于你 / 规格）是 P4 信任链的支撑，不单独设页。

## IA 树
```
TimeTrace · 一刻（单页长滚动）
├── 顶部粘性导航：品牌 · 为什么 / 界面 / 隐私 / 规格 / 常见问题 · 下载 v0.5.6
├── P1 首页 ── 主张 · 双 CTA · 版本事实行 · Hero 界面大图（含来源徽标）
├── P2 为什么 ── 统一白面板三行：不上传 / 不评判 / 不收费
├── P3 界面 ── 分段控件 + 四张真实截图 + 说明文案 + 演示数据声明
├── 数据属于你 ── 统一白面板四行：导出 / 备份恢复 / 整库迁移 / 清除
├── P4 隐私 ── 单一面板内两列对照：会记录 / 不记录 + 脚注
├── 规格 ── 两列六项定义列表
├── P5 下载 ── 彩色 CTA（玻璃按钮 + 光晕）+ 单个 setup + 诚实提示
├── FAQ ── 五问五答
└── 页脚 ── 版权 · 源码 / 发布仓 / 更新清单 / 回到顶部
```

## 设计理由
- **主张与真实截图前置**：这是工具类产品，访客先看「长什么样」再决定要不要读文字；截图同时承担「最新版本」的证据作用。
- **信任链按疑虑顺序排**：先回答「会不会上传」，再回答「能不能看时间」，最后回答「能不能删」。隐私敏感型用户的顾虑顺序就是 IA 顺序。
- **下载 CTA 放在疑虑清空之后**：P5 是完整说明区；按用户后续指令，顶部导航与首屏 CTA 改为同链直达下载，作为「不想读、直接下」的快捷路径，三处入口共用同一条已验证直链，不制造第二个转化目标。
- **不做多页**：内容量只够一页长滚动；拆页会增加跳转成本，且 GitHub Pages 用户站点不需要路由。
- **统一面板而非卡片墙**：三个「不」、数据能力、FAQ 都是同类条目，按 Apple Craft 的反碎片化规则放进一块白面板，用发丝线分隔。
