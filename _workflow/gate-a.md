# Gate A · 是否需要视觉升级

| 维度 | 判定 | 分数 | 理由 |
|---|---|---:|---|
| 交付对象 | 客户 / 老板 / 投资人演示档（对外公网官网） | 2 | 站点面向陌生访客，不是内部研发对齐 |
| 产品形态 | 官网 / 落地页 / 品牌 / C 端 | 2 | 产品宣传落地页，非中后台 |
| 用户措辞 | 「高级、质感」档 | 2 | 用户显式指定 `apple-craft`，等价于对视觉质感提出明确要求 |
| 主稿视觉自评 | ≥ 8 / 10 | 0 | S1 主稿直接以 Apple Craft 令牌为视觉基线，非草坯 |
| **合计** | | **6** | **≥ 3 → 走 S2 完整视觉升级** |

## 裁决（重要，说明为什么没有加载 `hifi-prototype`）
用户在同一轮显式指定了两个技能：`ui-design-pipeline`（流程）与 `apple-craft`（视觉系统）。流水线 S2 默认走 `hifi-prototype` 主题库，但流水线自身的两条硬规则是「一次只加载一个阶段技能」与「一套令牌一套值」——若再移植第二套主题，会与 Apple Craft 的 `tokens.css` 互相覆盖，产出四不像。

因此裁决为：**Apple Craft 的 `tokens.css` / `design-system.md` 作为本项目唯一视觉真源，在 S1 主稿阶段即落地**；S2 阶段执行的是等价工作——令牌完整性核验、对比度校验、动效补齐、三档视口冒烟，而不是再引入一套主题。这满足 Gate A「≥3 分需完整视觉升级」的意图，同时不违反「一套令牌一套值」。

理由优先级：用户显式指定的技能 > 流水线默认阶段技能；流水线冲突裁决第 3 条 > S2 默认路径。
