# 00 · 需求卡（S0）

## 定位
TimeTrace · 一刻的对外宣传落地页官网，托管在 GitHub Pages 用户站点 `zzjzgz.github.io`。让陌生访客在 30 秒内回答三件事：这是什么、为什么可信、怎么拿到。

## 用户
- 主要：Windows 桌面用户，想知道「我的电脑时间花在哪里了」，同时对云同步、账号体系、订阅制有戒心。
- 次要：开发者与效率工具爱好者，会核对技术栈并点开源码。
- 场景：从 README、熟人分享或搜索结果点进来，桌面或手机浏览器阅读，碎片时间、不会读第二遍。

## 核心任务（黄金流，详见 01-ia.md）
打开首页 → 看到一句话主张与真实界面 → 用「三个不」判断可信度 → 用四个视图确认功能 → 核对隐私边界 → 顶部导航 / 首屏 CTA / 下载区任一入口点击即下载 setup.exe。

## 一期范围（P0）
单页长滚动，5 个区段：P1 首页 / P2 为什么 / P3 界面 / P4 隐私 / P5 下载。
明确不做：博客、文档站、更新日志页、多语言、后台、埋点统计、下载计数、评论区。

## 交付对象
公网访客（对外产品官网）+ 后续维护者（研发交接包）。

## 输出形态
零构建单文件 `index.html`，双击可开；图片走本地相对路径 `assets/screens/*.png`；无 CDN、无外链字体、无构建链。

## 视觉基调
Apple Craft：`#f5f5f7` 冷灰白地面、统一白面板 + 发丝分隔、单一强调蓝、大标题负字距、克制的四档动效。

## 约束
1. 落地页图片必须从当前源码重新构建后真实运行截取，不得复用仓库遗留的历史截图。
2. 所有事实（版本、功能、许可、下载入口）必须可核对；无法核实的数字不写。
3. 未经用户明确指令，不执行 `git commit` / `git push`。
4. `check_design_pack.py --strict` 必须 FAIL = 0，且交付前做反向验证。

## Design Context（S3 输入，原样传递）
- **受众**：对隐私敏感、讨厌账号与订阅的 Windows 用户；其中一部分会读源码。
- **用例**：首次了解产品 → 判断可信 → 下载；手机上也看，注意力短。
- **品牌气质**：克制、诚实、安静、有点较真。不吹效率、不喊口号、不做焦虑营销。

## 假设与待确认
1. 域名沿用 `https://zzjzgz.github.io`（用户站点仓库，仓库名 = 用户名）。
2. 版本采用 **0.5.6**：`latest.json`、`app/package.json`、`Cargo.toml`、`tauri.conf.json`、CHANGELOG 一致；顶层 README 下载段仍写 0.5.5，判定为文档滞后，已在 HANDOFF「已知限制」登记。
3. 按用户后续指令，下载区只保留一个 setup 按钮；顶部导航、首屏「下载 Windows 版」、CTA 三处入口共用用户指定的发行版直链（实查 302 有效）。免安装单文件与 MSI 的同模式直链实查 404，不设按钮，仅在提示文案中给出 `releases/v0.5.6` 目录。
4. 界面截图用内置演示快照渲染，页面已明确标注「演示数据，不是任何真实用户的记录」。
5. 待用户确认：本次改动是否需要提交并推送到 GitHub。
